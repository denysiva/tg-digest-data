## F. ПРАВИЛА ПРОТИ AI-ТОНУ (загальні)

1. **Em-dash**: український longform природно використовує — частіше за англ. АЛЕ якщо у 3 реченнях поспіль є em-dash — це AI-pattern. Threshold для overuse: >1 em-dash на речення у середньому, або 3 em-dashes у 3 послідовних реченнях. Конвертуй більшість на коми/крапки/дужки, em-dash залиш тільки де реально emphatic.
2. **Rule of three** («A, B, та C») — помірно, не у кожному реченні. Особливо заборонено «якісно, швидко та зручно», «просто, ефективно та надійно», «професіоналізм, відданість та орієнтованість».
3. **Конкретна attribution**: ім'я + джерело (Бен Радак з X, Джон Касто з Bulletproof Scaling). НЕ «експерти», «практики», «багато хто», «спільнота кажуть».
4. **Active voice**: «команда запустила» > «було запущено».
5. **Negative parallelism** («не просто X — це Y», «не лише A, це B», «не випадково…», «не дарма…») — max 1-2 на дайджест.
6. **Filler BAN**: «варто зазначити», «слід підкреслити», «крім того», «не зайвим буде сказати».
7. **БЕЗ inflation**: «це не tool, це революція» — drop. Описуй що робить.
8. **БЕЗ self-introduction**: «дозвольте розповісти», «перед вами», «цей розділ присвячений».
9. **Mechanical bold у списках** — заборонено `**Швидкість:** ...`, `**Якість:** ...` патерн. Або проза, або просто текст без bold-headers.
10. **Title Case у заголовках** — заборонено («Як Ми Працюємо З Партнерами»). UA = sentence case («Як ми працюємо з партнерами»).
11. **Curly quotes** «"..."» — заборонено. UA primary = «…», nested = „…".
12. **Excessive hedging** stack («цілком ймовірно, що, як правило...») — максимум 1 hedge на claim.
13. **Emojis помірно (v11.4 rule)**: section markers OK (📊 для TG, 🛡️ для Meta-risk, 🔄 для Updates section, 📈 для тренду, ⚡ для action). In-text emojis у середині абзаців — мінімум, тільки коли реально посилюють емоцію. Не закидати кожне речення емоджі. Decoration emojis у списках (• ✅ ⭐ 🎯 у кожному рядку) — БАН.

## G. TEMA-REMA (порядок слів)

В українському нейтральному реченні **нова інформація йде у кінці**. Це створює природний «ткацький» ритм:

❌ Bad (front-loaded verb): «Платформа дозволяє баєрам автоматизувати запуск кампаній»
✅ Better: «Баєри запускають кампанії автоматично через платформу»

Якщо КОЖНЕ речення абзацу починається однаковим конструктом («Платформа надає…», «Платформа забезпечує…», «Платформа дозволяє…») — це AI pattern. Переплети sentence subjects.

## H. SENTENCE RHYTHM

Реальна укр-проза дихає різними довжинами:
- Short (3-8 слів): для емфази, фрагмент. Помірно.
- Medium (10-18 слів): робоча довжина.
- Long (20-30 слів): для складних думок.
- Very long (30+ слів): рідко, лише коли синтаксис справді потрібен.

Якщо 5 речень поспіль мають по ~14 слів — це AI block-prose. Розбий ритм.

**Парцеляція** — український ритмічний інструмент: розбий те, що могло б бути одним реченням, на два для емфази. «Бюджет. Періодично мені дзвонять із запитом…»

## ⚠️ Failure handling

- **Notion MCP error** (timeout, 5xx, auth fail): пости alert у Slack alerts channel через webhook:
  ```
  ⚠️ Anti-dup: Notion MCP unreachable — <error>. Digest продовжується БЕЗ exclude.
  ```

- **0 child pages returned**: ймовірно перший запуск або порожня parent — alert (warning level) + продовж нормально з пом'якою `Anti-dup: 0 prior pages found`.
- **<2 з 5 pages з body**: alert (warning) + продовж з тим що є.
- **Time budget**: 60s на anti-dup. Якщо timeout → alert + продовж без exclude.

«1:1 повторює» = entity candidate matches (case-insensitive substring) будь-який H1/H2 з TOPICS_RECENT БЕЗ нового update-angle.

## КРОК 4 — Synthesis: чорновик TOP-10

Read 6 candidate files + `/tmp/raw_meta.json` + `/tmp/raw_cross_source.json` + `/tmp/topics_recent.json`.

## Filter

- Виключи кандидатів з `In-TOPICS_RECENT=так` БЕЗ Update-angle
- Кандидатів з `так` + Update-angle — title = «UPDATE: …»

## Selection — v11.4 (use rules from «TOP-10 structure» section above)

**Apply lock & precedence:**
1. **Spots 1-3 = ОБОВ'ЯЗКОВО cases з цифрами** (case_with_numbers=yes), якщо такі є.
2. **Spots 1-4 = Meta forced** (Cases-Meta overlap OK — один спот закриває обидва).
3. **Spots 5-10 = remaining by Final score** (Final formula у «Scoring (M/A) — v11.4» section).

**70/30 action/context balance** — ≥7 з 10 sигналів action items, ≤3 context. Якщо переважає context — переглянь, прибери надмірний.

## Track priority_count_in_top10

При відборі — count = `sum(1 for c in top10 if c.Priority-source == 'yes')`. Запам'ятай це число для footer.

## Per signal output

3-5 речень фактів з контекстом + opt quote (UA/EN verbatim; RU перекладена українською з маркером). **Recommendation block — ОПЦІЙНО, тільки для action-items** (загроза/можливість/lifehack). Чисті news/context — БЕЗ рекомендації.

## Variable TOP-N (per data volume — v11.4 rules)

- ≥10 worthy candidates after anti-dup → **TOP-10** (default template)
- 5-9 worthy → **TOP-5** (quiet day template)
- 3-4 worthy → **TOP-3** (very quiet day template)
- <3 worthy → empty day template + skip Notion deep-dive (КРОК 7) + alert у Slack alerts webhook

## 🪞 КРОК 5 — 4-ПАСНИЙ РЕДАКТОРСЬКИЙ ПРОЦЕС (НАЙКРИТИЧНІШИЙ)

Без цього текст звучить як AI-звіт. НЕ пропускай (хіба що на >500K tokens — тоді можеш пропустити 5.1, але 5.2-5.4 + self-audit обов'язкові).

### Pass 5.1 — Quick triage + targeted improvement (concrete edits, не meta-talk)
Прочитай чорновик TOP-10. Для кожного сигналу:
1. Поміть: skim-readable (1-2 речення передають суть) чи deep (треба весь параграф)?
2. Знайди НАЙСЛАБШЕ речення (підпорний для розуміння, але неточне / fluff / repeats). Перепиши його.
3. Якщо сигнал має quote — перевір що quote є verbatim з оригіналом і у правильній мові (з суфіксом якщо не-UA).

Output: TOP-10 з 1 переписаним реченням на сигнал + verified quotes.

### Pass 5.2 — Copyedit (русизми, кальки, бюрократизм)
Для кожного речення перевір за таблицями С, D, B:
- Російська калька? → заміни (таблиця C)
- Канцелярит? → plain Ukrainian (таблиця D)
- Англіцизм без перекладу при першій згадці? → додай переклад у дужках (таблиця B)
- «Які» vs «що» — modern UA prefers «що» для restrictive clauses
- **Quote integrity**: UA/EN цитати 1-в-1 з оригіналом. **Russian цитати ОБОВ'ЯЗКОВО перекладено на українську** з маркером `(переклад з рос.)` після автора (per ЦИТАТИ section + Денис's policy 2026-05-16).

### Pass 5.3 — Editor pass (read it like a magazine editor)
- Чи звучить це як українська людина сказала б уголос?
- Чи природні word combinations? («глибока повага» не «сильна повага», «надійний партнер» не «стабільний партнер»)
- Чи правильний tema-rema (новий info у кінці)?
- Чи відсутні fake-deep transitions («Адже саме завдяки цьому…», «Не випадково…»)
- Чи sentence case у заголовках (не Title Case)?

### Pass 5.4 — AI-marker scrub (секція E)
- Generic openers — нема?
- Significance puffery — нема?
- Sycophancy — нема?
- Forced rule of three — нема?
- Negative parallelism — max 1-2?
- Robotic connectors («наразі», «відтак», «таким чином», «зокрема» з overuse) — почистив?
- Em-dash overuse (>1 на речення у середньому або 3 у 3 послідовних реченнях) — нема?
- Mechanical bold у inline-headers — нема?
- Curly quotes — нема? (UA = «…»)

**Для кожного signal у TOP-10 (і у "Також у дайджесті" 11-30) — застосуй цей checklist:**

#### A. Заголовок (1 рядок)
- ❌ Старий патерн: «Meta Performance Summit: Andromeda + ARM + Lattice + GEM ламають last-click — @andrewfoxwell» (назва події + 4 jargon терміни + хто сказав)

- Правило: заголовок має передати MAIN POINT, не назвати тему. Якщо читач не прочитає тіло — заголовок має дати йому розуміння.

#### B. Body структура — 3 секції з bold-маркерами

Замість wall-of-text — три секції:

1. **Що сталось.** — 2-4 речення. Хто/що/коли/де. Якщо актор не очевидний — короткий контекст («Ендрю Фоксвелл — відомий performance-маркетер»). Прибрати ARM/Lattice/GEM/identity тощо — замінити на принцип («новий стек з 4 систем що працюють разом»).
2. **Чому це вже болить / Чому це важливо.** — 2-3 речення з конкретними цифрами. Якщо є >1 число — bullet list:
   ```
   • 81% груп оголошень застрягли у фазі навчання
   • 72% креативів не дали жодної покупки
   ```
3. **Що робити цього тижня.** — numbered list якщо є послідовність кроків, інакше bullet. Для ролей — `*Тімлідам*` / `*Розробникам*` / `*Дизайнерам*` курсивом, БЕЗ emoji.

Незалежно від мови оригіналу (UA/RU/EN) — цитата у Slack українською. Маркер після автора: `(переклад з англ.)` або `(переклад з рос.)`.

❌ Старий: `> 💬 *@andrewfoxwell* (англ.): «Companies that wait until these trends are obvious will find themselves playing catch-up»`
✅ Новий: `> 💬 *@andrewfoxwell* (переклад з англ.): «Компанії, які чекають, поки тренд стане очевидним, гратимуть в наздогін за тими, хто вже зібрав дані»`

(Українські цитати залишаються as-is, без marker.)

Для кожного терміна у тексті:
- У білому списку (ROAS, CPM, hook, ad-set, audience) — НЕ пояснюй
- У чорному списку (Andromeda, ARM, CAPI, BM2500, learning phase) — пояснення в дужках при першій згадці
- У забороненому (triadic, point of friction, mass-AI-slop) — replace на українську (див. глосарій вище)

- Прибери emoji-категорії перед заголовком (вже є номер)

- Залиши тільки: 💬 перед quote, 1 для signal-type (опц. — якщо реально допомагає сканувати)

#### F. Абзаци ≤ 60 слів

Якщо абзац довше — розбий. Wall-of-text вбиває скан-читання у Slack.

#### G. Заборона cross-references

Прибери будь-які згадки: «У попередніх дайджестах ми фіксували X», «Резонує з #4», «Як ми обговорювали раніше». Це додає mental load. Все що читач має зрозуміти — у цьому signal.

#### H. Cases — обов'язковий контекст + ПРОЦЕС, не цифри (v11.7 critical)

Якщо це кейс (signal у spots 6-8), перевір що є **3 з 4** контекстних елементів:
- ✅ Бренд (назва або сфера: «supplement-бренд», «ecom DTC»)
- ✅ Вертикаль (нутра / гемблінг / SaaS / dating / etc.)
- ✅ GEO (US / UK / EU / CIS / global)
- ✅ Сума (revenue / spend / MRR)

Якщо немає 3+ елементів — кейс іде у «Також у дайджесті» (Notion-only), НЕ у Slack TOP.

**v11.7 NEW — Case narrative structure (4 секції замість загальної 3-секційної):**

Денис: «мене не дуже цікавлять ці цифри, як так вони з цього досягли, що вони робили і що стало цим тригером». Кейс — це не «$X → $Y», це ІСТОРІЯ. Структура:

1. **Тригер.** Що змусило команду/людину спробувати щось нове? Який insight, проблема, гіпотеза. Що вони помітили що інші не бачили? (1-2 речення)
2. **Що зробили.** Конкретні дії крок за кроком. Не «змінили стратегію», а «знизили ціну з $59 до $49, залишили креатив той самий, переключили на broad audience замість lookalike». Конкретика. (2-4 речення)
3. **Що змінилось.** Результат — тут можуть бути цифри, але як ОДНА з кількох змін, не основа. «Конверсія зросла на 18%, АЛЕ маржа впала з 41% до 28%». Не «-12% CPA», а «що це означало для бізнесу». (2-3 речення)
4. **Чому це працює (mechanism).** Найважливіше — РОЗУМІННЯ. Чому саме цей крок дав цей результат? Який психологічний / алгоритмічний / економічний механізм у грі? (2-3 речення)

**Без секції «Чому це працює» — кейс безкорисний.** Цифри без розуміння — це порнографія для аналітиків, не actionable insight.

#### Golden example for case (v11.7)

❌ **Поганий кейс (v11.4 production style — суха статистика):**

> _Кейс: ціна $59 → $69 додала 8 пунктів маржі — @fedotoff90_ (⚫)
> Дмитро Федотов (@fedotoff90, X, ❤ 26, 1 924 переглядів) опублікував рідкісний triadic-кейс. У лютому опустили ціну з $59 до $49 — CVR +0,4 пункти, обсяг +18%, але contribution margin впав з 41% до 28%. Через три місяці підняли до $69 — CVR -0,2 пункти, маржа стрибнула до 49%.
>
> _Рекомендація_: 📊 Senior buyers — тест підняття ціни на 15-20% без змін у creative/landing. Виміряй contribution margin post-shipping за 14 днів.

**Що не так:** Сухі цифри. Junior читач не розуміє ЧОМУ це працює. Senior читач теж — це може бути просто «їхня аудиторія price-insensitive», а може бути загальний принцип. Mechanism відсутній.

✅ **Добрий кейс (v11.7 narrative style):**

> *6. ecom-бренд знизив ціну з $59 до $49 «щоб розігнати конверсію» — і отримав менше прибутку при більших продажах. Урок про price-sensitivity*
>
> **Тригер.** Дмитро Федотов (відомий ecom-консультант) ділиться кейсом з US-бренду супплементів. Команда побачила «застрягання» на BEROAS 2,2 (мінімальний ROAS щоб вийти в нуль) і вирішила, що проблема у ціні — мовляв, $59 занадто дорого для теплої аудиторії, давайте знизимо.
>
> **Що зробили.** У лютому опустили ціну з $59 до $49 без жодних інших змін — той самий креатив, та сама воронка, той самий лендінг. Хотіли побачити «чистий» вплив ціни на конверсію. Через три місяці, коли побачили результат, зробили зворотний хід — підняли до $69.
>
> **Що змінилось.** На $49 продажі дійсно виросли на 18% (більше людей купило), конверсія підросла на 0,4 пункти. Але маржа на одиницю впала з 41% до 28% — тобто компанія заробила менше грошей при більших продажах. На $69 ситуація стала зворотною: продажі мінус 0,2 пункти конверсії, але маржа стрибнула до 49%.
>
> **Чому це працює.** Знижка не «привертає» нових клієнтів — вона дає тим, хто і так купив би, заплатити менше. Це класичний феномен у ecom: люди, які купують $59-продукт, не зникають при $69 — вони просто платять. Знижка створює видимість росту (графіки гарніші, дашборди зеленіші), але реальний прибуток падає. Урок: revenue — це поганий proxy успіху; contribution margin (маржа після всіх змінних витрат — виробництво + доставка) показує реальність.
>
> > 💬 *@fedotoff90* (переклад з англ.): «Більшість ecom-підприємців роблять знижки, бо не довіряють власному офферу. Це і є реальна проблема»
>
> **Що робити цього тижня:**
> 1. *Senior buyers* — якщо ваш оффер крутиться на BEROAS 2,2-2,5 і ви скейлите через bid strategy, паралельно протестуйте підняття ціни на 15-20% без змін у креативі чи лендингу. Заміряйте contribution margin (а не revenue) за 14 днів.
> 2. *Operations* — додайте у щомісячний фінансовий звіт поле «contribution margin після доставки по SKU». Якщо менше 35% — поточна ціна занижена.

**Що змінилось:**
- Sole header «$59 → $69 додала 8 пунктів маржі» (статистика) → «знизив ціну щоб розігнати конверсію — і отримав менше прибутку. Урок про price-sensitivity» (mechanism + lesson)
- 1 wall з цифрами → 4 секції (Тригер / Що зробили / Що змінилось / Чому працює)
- «triadic-кейс» → видалено (заборонений термін)
- BEROAS пояснено при першій згадці
- Contribution margin пояснено при першій згадці
- Mechanism explanation («знижка не привертає клієнтів, дає тим хто купив би заплатити менше») — головний takeaway, якого не було у v11.4
